## 一、参数冻结与核对

`alba9_param_table.m` 从 `ALBA_Stage8_Results.mat`（SHA256
`547170400466c726601d6b03f8b4970b239e920263faaa8f9a7f5c9e880c5b3f`）重算
`alba9_const.m` 的每一个常数并逐位比对：

> **26 个常数全部完全相等，最大 |差值| = 0。** 不一致会直接报错而不是告警。

请求中点名的数值全部单独断言通过：初始水量 500 mL、自然外径 70 mm / 内径 66 mm、
硅胶体积 2.9061826440808009e-5 m³、500 mL 时外径 0.10034658601199008 m、
鱼线径向间距 3 mm、最小外径 50 mm、笼架 0.270 kg、助流压头 +981 Pa、
Rh = 1.6440083045256217e9 Pa·s/m³、管内径 4 mm / 总长 0.36 m、
裸轴半径 0.0025 m / 3200 STEP/rev、ku = 4.9087385212340526e-6 m/STEP。

断言过程中澄清了两处容易误读的定义：

- **2 mm 是模具单侧壁厚**，由 (70−66)/2 得到，程序里断言的就是这个读法；
  它不是充水后的壁厚，模型任何地方都没有把它当作充水壁厚使用。
- **Vmin 是 50 mm 外径下的"水量"**，不是球体积。等效球包含硅胶，
  所以 Vmin = π/6·0.05³ − V_silicone = 3.6388e-5 m³。
  最初的断言漏减了硅胶体积而报错，这正是断言该起的作用。

整数转 double 的兼容性修正全部保留（`alba9_make_params.m` 逐字段 `double()`，
以及 `stage8_matlab_fix/rom3_rhs.m`）。ROM 系数从 MAT 原精度读入，未手抄、未舍入、未回归。

**参数表**：`parameter_table.md` / `.csv`，78 行，每行标注单位、来源和假设属性。
状态词表刻意收窄为 `given / derived / assumption / learned / solver / legacy / metadata`，
使任何未测量的量都不可能被悄悄写成"实测"。表内无任何一行是实验验证过的硬件值。
`material_relaxation_source` 曾被标为 UNANNOTATED 并已补齐——未标注字段是被报出来的，不是被丢弃的。

表中特别标注的三条：

- `Rh` 命名为 **bench effective resistance**（整条水路的台架等效阻力），
  不叫 4 mm outlet resistance，不是已辨识的阀门曲线。
- `force_max = 15 N` 标为 **legacy**：旧力夹具限制，**不是本阶段电机能力上限**，
  不得用来替代转矩—相位模型。
- `0–118 N` 标为 **learned 的已审查范围上界**，不是电机力上限，模型里也没有力饱和。

## 二、关阀事件修正（最优先）

### 缺陷确认

从 v1 的结果文件直接统计阀门状态跳变，你给的数字逐条对上：

| v1 工况 | open→closed | closed→open |
|---|---:|---:|
| 200 mL 前馈+PI | 13 | **12** |
| 300 mL 纯 PI | 22 | **21** |
| 300 mL 固定步频 | 1 | 0 |
| 300 / 400 mL 前馈+PI | 1 | 0 |

成因确认为：关阀后膀胱水量冻结在**恰好等于阈值**处，求解器为定位零跨越会在开阀一侧
重复求值，直接比较器随之抖动。每一次抖动都会重新触发 Q 清零，并让关阀时刻与 q0 锁存重新开始积分。

### 修正

`build_alba9_model.m` 改为：原始比较器 → **单调锁存积分器**（输入 ≥ 0，输出钳位 [0,1]）
→ 阀门标志取 `latch ≥ 0.5`。单调状态只可能向上穿越 0.5 一次且永不返回，
因此 **1 次 open→closed、0 次 closed→open 是构造保证的，不是靠容差、日志过滤或平滑得到的**。
原始比较器仍然逐点记录在 `cmp_raw` 通道里，抖动是被吸收而不是被抹掉。

- t=0 开阀，电机指令同步启动，鱼线初始张紧，无人为等待、无松线段（未改动）。
- Q 的外部复位由**锁存后**的标志驱动，因此只在第一次关阀事件清零一次。
- `Int_tc`（关阀时刻）与 `Int_q0`（关阀前流量）输入为 (1−阀关闭)，只冻结一次、永不重启。

### 验证结果

9 个工况（200/300/400 mL × 3 种控制结构）全部：**open→closed = 1，closed→open = 0**。

代价是一个确定性的关阀延迟 = 0.5/latch_gain = **5 µs**，对应多放过的体积：

| 工况 | 关阀前流量 | 延迟放过体积 |
|---|---:|---:|
| 前馈+PI / 纯 PI | ≈3 mL/s | 1.5×10⁻⁵ mL |
| 固定步频 300 mL | 8.66 mL/s | 4.3×10⁻⁵ mL |

这个延迟在诊断里逐工况报出，没有藏起来。它也正好解释了与独立 ODE 实现之间
5×10⁻⁶ s 的关阀时刻差和 1.5×10⁻⁵ mL 的体积差——差异被完整归因，不是残余误差。

### q0 的性质：已明确，并已量化

`Int_q0` 是时间常数 `tau_q0 = 1 ms` 的一阶跟踪器在关阀时冻结，**不是 Q 的精确左极限**。
独立 ODE 实现用终止事件，天然给出精确左极限，两者对比：

| 工况 | 模型实际使用的 q0 | 精确左极限 | 差 |
|---|---:|---:|---:|
| 200 mL 前馈+PI | 2.99994 | 2.99994 | −4.1×10⁻⁷ |
| 300 mL 前馈+PI | 2.99955 | 2.99955 | −2.0×10⁻⁶ |
| 400 mL 前馈+PI | 2.99904 | 2.99904 | −1.9×10⁻⁶ |
| 300 mL 纯 PI | 2.99719 | 2.99719 | +2.6×10⁻⁶ |
| **300 mL 固定步频** | **8.65999** | **8.65977** | **+2.2×10⁻⁴** |

闭环三个工况关阀前流量已被稳在 3 mL/s，跟踪滞后几乎不产生误差；
固定步频关阀时流量高且仍在变化，误差大两个数量级——这正是该量化的地方。
所有捕获都发生在 Q 清零之前（锁存冻结与复位由同一个单调标志驱动）。

## 三、诊断修正（先修统计，不动控制器）

### 1. 固定步频不再把真实误差记成零

`alba9_controller.m` 现在**始终**返回 `e_track = Qref − Q`，
固定步频分支仍然开环（`e_track` 只记录、不反馈，控制律未变）。
v1 在该分支把 `e = 0` 写进日志，等于把一个真实的跟踪误差抹掉。
修正后 300 mL 固定步频的平台时间加权 RMSE 记录为 **3.4552 mL/s**，启动段 6.6743 mL/s。

### 2. 平台统计改为时间加权，并明确分段

分段定义写进诊断输出：启动 = 开阀且 t ≤ 2 s；平台 = 开阀、过了启动、参考仍在设计平台；
减速 = 开阀且参考已低于平台；关阀段单列。开阀段与关阀段**分别去重、分别积分**，
任何统计都不跨越关阀处的流量跳变。

**这一项改变了结论，必须明说：**

| 工况 | v1 平台最差偏差 | v2 平台最差偏差 | v1 RMSE | v2 时间加权 | v2 未加权 |
|---|---:|---:|---:|---:|---:|
| 200 mL 前馈+PI | +0.96% | **+2.38%** | 0.0155 | 0.0429 | 0.0940 |
| 300 mL 前馈+PI | +0.96% | **+2.38%** | 0.0123 | 0.0334 | 0.0745 |
| 400 mL 前馈+PI | +0.96% | **+2.38%** | 0.0109 | 0.0284 | 0.0636 |
| 300 mL 纯 PI | +0.91% | **+1.27%** | 0.0409 | 0.0434 | 0.0530 |
| 300 mL 固定步频 | +37.71% | +37.56% | 3.4867 | 3.4552 | 3.4559 |

两个原因：

- **v1 的平台窗口从 `rise_s + 0.2 s` 开始。** 那 0.2 s 的跳过没有任何依据，
  而升流段交班处的过冲峰恰好落在里面。去掉这个人为跳过后，前馈+PI 的平台峰值
  从 15.1446 变成 **15.3564 mL/s**。**v1 报的 +0.96% 是这个窗口造成的，不是真实的平台偏差。**
- v1 用的是未加权样本 RMSE，会按变步长求解器的采样密度加权。前馈+PI 上两者差 2.2 倍
  （0.0334 对 0.0745）；固定步频误差大而平缓，两者几乎相同（3.4552 对 3.4559）。

三档体积仍然满足草案建议的 ±5%，但真实裕度是 2.38%，不是 0.96%。

### 3. 指令斜率分别核查

| 工况 | 开阀段 max (限 6000) | 关阀制动段 max (限 2000) |
|---|---:|---:|
| 200/300/400 mL 前馈+PI | 1217.96 ok | 2000.00 ok |
| 300 mL 纯 PI | 1194.25 ok | 2000.00 ok |
| 300 mL 固定步频 | **6000.00 ok**（启动段被限幅 0.0962 s） | 2000.00 ok |

不再用较大的 6000 一刀切判定全部通过。另外指令加速度改为**直接记录施加值**
而不是对变步长日志做差分——v1 的差分法在关阀处会报出控制器从未施加过的 6000.26。

### 4. 水量平衡：区分构造恒等式与真正的检查

`mass_balance_error` 改名为 `accounting_identity_error_mL` 并注明"不可能失败、不证明任何物理"。
新增三项独立计算：

| 工况 | ∫Q dt − 膀胱减少量 | ∫q_tail dt − 尾水状态 | 含管内存水的总量 |
|---|---:|---:|---:|
| 200 mL 前馈+PI | −7.70×10⁻⁵ mL | +1.20×10⁻⁴ mL | 0 |
| 300 mL 前馈+PI | −3.91×10⁻⁵ | +9.49×10⁻⁵ | 0 |
| 400 mL 前馈+PI | −5.73×10⁻⁶ | +1.29×10⁻⁴ | 5.7×10⁻¹⁴ |
| 300 mL 纯 PI | −7.36×10⁻⁵ | +1.38×10⁻⁴ | 5.7×10⁻¹⁴ |
| 300 mL 固定步频 | −2.55×10⁻⁴ | −6.14×10⁻⁶ | 0 |

前两项是真检查：从日志重新积分，对上求解器积分出来的状态。
第三项（含 4.5239 mL 管内初始存水）在前两项成立后就是恒等式，如实标注。
关阀后的尾水**没有**从膀胱再扣一次。

### 5. 事件与状态记录

每个工况的 `.log`（JSON）现在包含：阀门与原始比较器的跳变计数、关阀时刻、
锁存延迟及其体积代价、实际使用的 q0 与精确左极限之差、停止收线时刻、尾水结束时刻、
尾流时长及其外推性质、PI 积分器终值与最大值、指令饱和累计时长、斜率限幅累计时长、
分段统计、五项平衡、以及与独立 ODE 的整轨迹比较。不再只输出汇总最大值。

### 6. 收紧容差 + 整轨迹核对

每个工况都与**独立的 ode15s 实现**在整条轨迹上比较（流量、水量、接触力、指令四个通道，
开阀段与关阀段分别比，关阀附近的窗口按差异宽度剔除并报出宽度），
再用 RelTol 1e-10 / MaxStep 0.0125 重跑一遍复核：

| 工况 | Δt_close | ΔQ (mL/s) | ΔV (mL) | ΔF (N) | Δn (STEP/s) |
|---|---:|---:|---:|---:|---:|
| 200 mL 前馈+PI | 5.00×10⁻⁶ | 2.6×10⁻⁶ | 1.5×10⁻⁵ | 7.5×10⁻⁴ | 1.0×10⁻² |
| 300 mL 前馈+PI | 5.03×10⁻⁶ | 2.6×10⁻⁶ | 1.5×10⁻⁵ | 9.6×10⁻⁴ | 1.0×10⁻² |
| 400 mL 前馈+PI | 4.95×10⁻⁶ | 2.6×10⁻⁶ | 1.5×10⁻⁵ | 1.4×10⁻³ | 9.9×10⁻³ |
| 300 mL 纯 PI | 4.90×10⁻⁶ | 2.1×10⁻⁶ | 1.5×10⁻⁵ | 9.3×10⁻⁴ | 9.8×10⁻³ |
| 300 mL 固定步频 | 5.00×10⁻⁶ | 3.1×10⁻⁷ | 4.3×10⁻⁵ | 2.7×10⁻³ | 1.0×10⁻² |

收紧容差后同量级（ΔQ 升到 2.7×10⁻⁵ mL/s，其余不变）。
Δt_close 与 ΔV 恰好等于锁存延迟及其体积代价，差异被完整归因。

**以上属于数值验证，不是实验验证。** 两套实现一致只说明同一组方程被正确地解了两次。

## 四、尾流假设

用户提供的信息是：尾水约 2 mL，曾观察到约 1.33 s 的持续。**半余弦形状仍是模型假设**，
`T = 2·V_tail/q0` 也是假设的规则。二者合起来只有在 q0 ≈ 3 mL/s 时才复现 1.33 s。

本阶段保留现有规则重跑基线，并把外推性质写进诊断：

| 工况 | 关阀时刻 | 关阀前流量 q0 | 尾流时长 T | 性质 |
|---|---:|---:|---:|---|
| 200 mL 前馈+PI | 16.7985 s | 2.99994 | 1.3334 s | 接近用户观察点 |
| 300 mL 前馈+PI | 23.4620 s | 2.99955 | 1.3335 s | 接近用户观察点 |
| 400 mL 前馈+PI | 30.1242 s | 2.99904 | 1.3338 s | 接近用户观察点 |
| 300 mL 纯 PI | 23.3704 s | 2.99719 | 1.3346 s | 接近用户观察点 |
| **300 mL 固定步频** | 25.6443 s | 8.65999 | **0.4619 s** | **外推假设，不是实测时间** |

"初始尾流等于关阀前流量、半余弦、2 mL、1.33 s"这四个条件不可能在所有工况同时成立，
程序也没有强行让它们同时成立。

三个时刻分别输出：

| 工况 | 关阀 | 停止收线 | 尾水结束 |
|---|---:|---:|---:|

**末端体积恰好等于目标不是控制精度的证明**，诊断里标为 `volume_error_is_bookkeeping_only`：
阀在理想体积事件上关闭，交付的尾水恰好等于补偿掉的尾水。真实尾水若为
1.0/1.5/2.5/3.0 mL，末端误差就是 −1.0/−0.5/+0.5/+1.0 mL。

## 五、程序修正**没有**改变的量

这一点同样要说清楚，否则容易把 v1 说得比实际更糟：

| 量 | v1 | v2-A |
|---|---:|---:|
| 关阀时刻（四个闭环工况） | 16.7985 / 23.4620 / 30.1242 / 23.3704 s | 完全相同 |
| 最大接触力 | 115.959 / 115.959 / 115.959 / 114.389 / 114.414 N | 完全相同 |
| 最大指令步频 | 782.55 / 973.32 / 1349.28 / 969.71 / 606.94 STEP/s | 完全相同 |
| 末端收集体积 | 目标 ±1×10⁻⁵ mL | 目标 +1×10⁻⁵…+4×10⁻⁵ mL（锁存延迟） |

也就是说：**关阀抖动是一个潜在缺陷，它在 v1 里恰好没有咬到结果**——
抖动都是零时长的日志点，没有实质改变轨迹。修掉它是为了让"只关一次"成为构造保证，
而不是为了纠正一个已经算错的数。真正被修正的结论是平台偏差 +0.96% → +2.38%。

## 六、本阶段仍未回答的问题

1. **转矩、电相位、实际转速、鱼线位移/张力、失步裕度全部无法在此检查。**
   ROM3 没有电机状态。绿色固定步频工况关阀后接触力从 33.88 N 升到 114.41 N
   （继续收线约 0.452 mm），这在图中完整保留、未做任何裁剪，
   但它是否在真实执行器上可行，必须由完整参考模型回答。
2. 反馈仍是理想无噪的，无量程、无量化、无噪声、无延迟。
3. 尾水体积与形状仍是假设，其不确定度直接进入末端体积误差。
